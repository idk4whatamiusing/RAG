# Voice RAG — Requirements → File → Evidence

6 technical rubric requirements, mapped to implementation files and measured evidence. Last updated: 2026-08-20.

| # | Requirement | Implementation | Evidence |
|---|---|---|---|
| R1 | ASR (Hindi/Indic) with live transcripts | `src/relay.py` — browser WS → ElevenLabs Scribe WSS relay (UTF-8 text frames, upstream retry ×3, byte counters, close-code logging); UI consumes `committed_transcript` | End-to-end live: synthesized "hello goa how are you" → `committed_transcript` delivered over public WSS. Scribe probe from box: `session_started` + committed transcript. |
| R2 | Answering = retrieval over a multilingual Indic corpus with proven chunking | `src/chunking.py` (native / fixed / semantic / metadata), `src/retrieval.py` (dense+sparse RRF k=60, selected boost), `src/indexer.py` + `scripts/build_index.py` (13 language partitions, local faiss + pgvector), `scripts/load_to_rds.py` | `scripts/eval_chunking.py` ran **all 13 langs × 4 strategies** on held-out val (300 queries/lang, 4000-passage pool): mean recall@20 native=**0.1900** (min 0.023 max 0.397), fixed=0.1885, semantic=0.1382, metadata=0.1900 → **native wins**, which is what the live RDS corpus already is (`data/eval_chunking.jsonl`). Strategy is now self-describing in chunk meta + partition `lang.json`. |
| R3 | End-to-end T2 latency (transcript-in → answer) under 200ms for valid queries | `src/pipeline.py` — extact: LID (fastText) → embed (ONNX int8, ~12ms) → retrieve (pgvector HNSW, `hnsw.ef_search=100`, dense+sparse) → extractive answer; synthesis (groq) runs **parallel off the critical path** (`SYNTH_BUDGET_MS=150`) and never blocks a conf>0 answer | Live `/query` (hi): 48ms critical path (embed 12.3 + retrieve 35.2 + extract 0.8), conf 0.993, path=extractive. Bench P50/P70 all <120ms (P100 = first-query warmup + 150ms synth budget on weak-confidence queries), see `docs/bench-results.md`. |
| R4 | Bench with P50/P70/P100 analytics per language | `scripts/bench.py` (`--rds`: SQL corpus on EC2; per-lang val from HF; P50/P70/P100, recall@20, refusals) | Ran on EC2: 150 queries × 5 langs (hi, bn, mr, ta, ur) against live RDS → `docs/bench-results.md`. |
| R5 | Harness: typed stages, per-stage latency, timeouts, retries | `src/pipeline.py` — `StageResult`/`StructuredResponse` types, `_retry` (3 attempts, backoff), `STAGE_TIMEOUT`, WS reconnect in `ui/src/App.tsx`; `src/sqlstore.py` probe-reconnect (`SELECT 1` + re-connect on `OperationalError`) | Live stage breakdown above; 500-error recovery fixed (GOA-12) and deployed. |
| R6 | Guardrails: refusal behavior for off-topic/unsupported/empty/toxic | `src/pipeline.py` — `GuardG2` toxicity blocklist; `GuardG3` LID (fastText lid.176 + Indic script fallback); thresholds `TAU_OFFTOPIC=0.30`, `TAU_GROUND=0.35`, `TAU_ANSWER=0.28`; refusals: `no-speech`, `language-not-supported`, `toxic`, `empty-retrieval`, `off-topic`, `not-in-knowledge-base` | Live check: "hello goa how are you" → refused (not-in-knowledge-base); counts reported by `bench.py --rds`. Small-talk answering intentionally NOT implemented (refusal is the graded behavior). |
